A critic, or a group of peers?

Two identical policy networks learn to balance an Acrobot. One learns from a value critic. The other compares eight attempts from the same starting state. Same reward, same step budget, three seeds each.

Failure modes to look for

Follow-up: test whether a designed controller can balance →

High but not balanced: the tip reaches the top with too much angular speed. Height rises while upright time stays low.

Local balancing only: strong near-upright results, weak hanging-down results. The policy has not learned swing-up.

Unstable learning: hold duration rises and then falls, or only one seed succeeds. A single good video hides this.

Action-selection mismatch: sampled actions perform well but the most-likely action fails, or vice versa.

Why the methods can fail

PPO: inaccurate critic targets can distort the step-by-step learning signal. A useful critic can instead make those signals much less noisy.

Grouped: every action in a trajectory receives the same relative score. Good swing-up decisions and a bad balancing correction get mixed together. Groups with equal returns provide no reward signal.

These are mechanisms to investigate, not causal conclusions established by the learning curves. Both methods can also exploit an imperfect reward.

Experiment protocol and downloads

Custom Gymnasium-compatible Acrobot: original dynamics and three torques (−1, 0, +1), 0.05s control interval, fixed 20s episodes, no success termination. Inputs: six state features plus remaining time. Each policy has two 64-unit Tanh layers. PPO has a separate critic of the same hidden size.

Training starts: 75% near upright, 25% hanging down. Both methods collect 8 groups × 8 trajectories per update. PPO uses GAE (λ=0.95); grouped uses normalized episode returns within each group. Both use γ=1, four clipped-update epochs, the same optimizer settings for the actor, and the same entropy bonus. This is a GRPO-inspired outcome-baseline comparison, without an LLM reference-policy KL penalty.

Reward per step: dt × [height + 2 × balanced − 0.05 × height⁴ × angular_speed²]. Training time excludes evaluation, video encoding, image build, and startup; simulator-step counts also exclude evaluation. Both run on the same CPU allocation. Chart evaluation uses seed 10000; final transfer evaluation uses seed 20000 if available.
